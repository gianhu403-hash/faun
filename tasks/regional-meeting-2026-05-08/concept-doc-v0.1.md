## 1. Executive Summary

Faun — отечественная **экоакустическая система мониторинга дикой природы**, которая в режиме реального времени выявляет браконьерство, незаконную рубку и присутствие техники, а также ведёт мониторинг и определение видов животных на ООПТ. Состоит из четырёх слоёв: сеть автономных датчиков → edge-обработка → облачный пайплайн → платформа для биологов и инспекторов.

За полгода командой собран **рабочий прототип всех четырёх слоёв** (доступен на `faun.antopkin.ru`, дев. до 1291 микрофона на тестовой территории), есть наработки по 10+ сервисам Yandex Cloud, экспертиза в YAMNet/TDOA, опыт CI/CD-деплоя.

**Что предлагается для пилота с Yandex Cloud:** ограниченный демонстратор — облачный конвейер распознавания видов на готовых записях Романа (180 ГБ). Архитектура — cloud-only, без edge и без триангуляции. Reference-модель — BirdNet (Cornell Lab). Deliverable — CSV-отчёт + минимальный web-эндпоинт «вставьте URL Я.Диска → получите CSV-ссылку». Срок — ~6 недель. Бюджет облачных ресурсов — **₽5–100 тыс. на весь пилот** (3 сценария ниже), это деньги Yandex Cloud в рамках выделенного облака, наша команда работает за свой счёт на этом этапе.

**Почему стоит:** пилот даёт Yandex Cloud (а) рабочий cloud-pipeline для одной из задач платформы Президентского фонда природы для ООПТ, (б) валидацию команды Faun как партнёра, (в) данные для оценки следующих фаз (масштабирование на терабайты сезонных данных, расширение на собственное железо, выход за пределы Yandex).

**Что НЕ обещаем в пилоте** (явно): real-time, edge inference, LoRa/GSM передачу событий, триангуляцию, распознавание антропогенных звуков, accuracy >80%. Всё это уже частично реализовано в Faun под лесные нарушения, но к пилоту с Yandex Cloud отношения не имеет.

## 2. Контекст и проблема

### 2.1 Боль рынка

В России ~14 000 ООПТ. Каждая из них сталкивается с тремя классами задач:

1. **Мониторинг биоразнообразия** — учёт видов, особенно редких и скрытных (садовые сони, выхухоль, прочие краснокнижные). Сейчас — ручные орнитологические маршруты, фотоловушки, выборочные исследования. Полнота низкая, частота низкая, сравнимость год-к-году плохая.
2. **Охрана** — выявление браконьерства, незаконных рубок, неавторизованной техники. Сейчас — рейды инспекторов, реакция по факту, обычно с задержкой в дни/недели.
3. **Цифровизация и отчётность** — Президентский фонд природы готовит платформу с цифровыми решениями для ООПТ. Запрос на стандартизованные, легко интегрируемые источники данных растёт.

Пассивный акустический мониторинг (passive acoustic monitoring, PAM) закрывает все три задачи одной инфраструктурой: один и тот же микрофон записывает и поющую птицу, и звук бензопилы — разделение делает программа. Это даёт **24/7 покрытие** без увеличения человеко-часов.

### 2.2 Что есть на рынке

**Готовые акустические регистраторы (hardware):**

| Решение | Цена ориентир | Сильные стороны | Слабые |
|---|---|---|---|
| Open Acoustic Devices AudioMoth | ~$80–100 | дешёвый, open-source | базовая запись, без передачи данных |
| Wildlife Acoustics Song Meter SM4 | ~$700–1000 | премиум-качество, надёжность | дорого, проприетарно |
| Cornell Swift | ~$500 | научный референс | мало доступен в РФ |
| BirdWeather PUC | ~$300 | автономность + сеть | США-ориентирован |
| Raspberry Pi + USB-микрофон | ~$80–200 | гибкость, кастомизация | DIY, нужна сборка |
| Haikubox | ~$400 | потребительский UX | США-ориентирован, узкая задача |
| Китайские ловушки (Роман привёз) | ~$? | защита от природы, неделя автономно | без передачи данных |

**Программные стеки распознавания:**

| Решение | Особенность |
|---|---|
| BirdNet / BirdNET-Analyzer (Cornell) | open-source, 6000+ видов, ~75% accuracy на чистом аудио |
| BirdNET-Pi | дистрибутив BirdNet под Raspberry Pi |
| Google Perch / Perch 2 (2025) | новая модель Google, потенциально точнее BirdNet, embeddings для retrieval |
| DS-Hub Sochi `wolf_sounds_demo` | российский кейс по распознаванию волков |
| YAMNet (наш v7) | базовая модель Faun под антропогенные звуки |

**Платформенные решения (как референс):**

- **ecopi LiveApp** (oekofor.de) — комбинация фото+аудиоловушек с координатами и временными метками, управление архивом, события. **Ближайший по форме референс для нашей платформы.**
- **Rainforest Connection / Guardian nodes** — anti-poaching через edge-inference + сетевая передача. Антропогенные звуки в фокусе.
- **eBird, iNaturalist, xeno-canto** — научные базы данных, источники ground truth для моделей.

**Чего на рынке нет:**

1. Российской платформы PAM, готовой к интеграции в платформу ООПТ Президентского фонда природы.
2. Системы, которая закрывает обе задачи одновременно — мониторинг видов *и* выявление антропогенных нарушений в реальном времени.
3. Hardware-стека с дешёвыми компонентами + edge-inference + передачей только событий через УКВ/LTE (а не сырого аудио).

Faun целится в эти три ниши одновременно.

### 2.3 Откуда мы

За полгода команда Faun (6 человек) собрала рабочий прототип системы:

- **3 Docker-сервиса** (`cloud`, `edge`, `lora_gateway`), CI/CD, авто-деплой на VPS.
- **ML-стек:** YAMNet v7 finetuned под 5 классов антропогенных звуков (chainsaw / gunshot / engine / axe / fire) с leak-free evaluation; TDOA v5 с 10 улучшениями (subpixel, PHAT-beta, median GCC, MAD, DEMON).
- **10+ сервисов Yandex Cloud в продакшене:** YandexGPT (алерты, юридизация), AI Studio Assistants API (RAG-агент), File Search RAG по 9 нормативным документам, Web Search, SpeechKit STT, Gemma 3 27B (Vision), Yandex Workflows (12-шаговый pipeline), Classification Agent, DataSphere (обучение моделей), DataLens (аналитика).
- **Дашборд** на Leaflet (canvas-рендеринг до 1291 микрофона), FastAPI-бэкенд, ~514 тестов pytest, всё в CI зелёное.
- **Доступно онлайн:** `https://faun.antopkin.ru` (телеграм-боты `@faun_forest_bot`, `@faun_drone_bot`).
- **Экспертиза партнёров:** контакты с MIEM/Бауманкой по array-акустике — потенциальный канал hardware-удешевления.

То есть Faun — это **не идея на бумаге**, это работающая система, изначально заточенная под лесные нарушения. Под биоразнообразие нужна **отдельная модель** (BirdNet вместо YAMNet) и переориентированный pipeline, но архитектура и большая часть инфраструктуры переиспользуются 1-в-1.

## 3. Продукт Faun — целевая система

### 3.1 Одной строкой

> Отечественная экоакустическая система мониторинга дикой природы: сеть автономных датчиков → edge-обработка → облачный пайплайн → платформа для биологов и инспекторов.

### 3.2 Архитектура верхнего уровня

```
                  Лес / ООПТ                                    Облако
┌─────────────────────────────────────────┐          ┌────────────────────────┐
│  Сеть акустических датчиков              │          │  Object Storage         │
│  • 24-бит / 48 кГц                       │   LTE    │  (сырое аудио,          │
│  • Триггер-запись (±10 с от события)     │ ──────►  │   агрегаты, события)    │
│  • Solar + Li-Ion аккумулятор            │ Wi-Fi    │                        │
│  • Edge inference (YAMNet / BirdNet      │   УКВ    │  Compute / DataSphere   │
│    лёгкая модель)                        │ ──────►  │  (классификация, пере-  │
│                                          │  только  │   обучение, аналитика)  │
│  ┌──────────┐  ┌──────────┐ ┌──────────┐ │  событие │                        │
│  │ датчик 1 │←─│ датчик 2 │─│ датчик N │ │          │  YandexGPT / RAG        │
│  └──────────┘  └──────────┘ └──────────┘ │          │  (алерты, юридизация)   │
│       ↕            ↕            ↕        │          │                        │
│   Триангуляция между датчиками           │          │  Платформа для         │
│   (направление + координаты события)     │          │  пользователя           │
└─────────────────────────────────────────┘          │  • дашборд + карта     │
                                                      │  • Telegram-бот        │
                                                      │  • CSV-отчёты          │
                                                      │  • DataLens-аналитика  │
                                                      └────────────────────────┘
```

### 3.3 Кто пользователи (3 профиля)

**Биолог ООПТ.** Раз в неделю забирает флешку из ловушки (или получает данные по сети), хочет за минуту видеть, какие виды и где зафиксированы. Боль: ручное прослушивание десятков часов записей. Ожидание: автоматический CSV-отчёт «трек / секунда / вид / вероятность» + карта.

**Экологический инспектор.** Должен реагировать на нарушения. Боль: рейды по графику, а не по событию; пилы и выстрелы в большинстве случаев фиксируются по следам. Ожидание: push в телефон через минуты после события, с координатами и направлением.

**Менеджер фонда / директор ООПТ.** Готовит отчёты, обосновывает финансирование, сравнивает территории и сезоны. Боль: разрозненные источники, ручная агрегация. Ожидание: дашборд с динамикой видов и инцидентов год-к-году.

### 3.4 Чем отличаемся

| | BirdNet (как софт) | RFCx Guardian | ecopi LiveApp | Wildlife Acoustics SM4 | **Faun** |
|---|---|---|---|---|---|
| Распознавание видов | ✅ | ⚠️ | ⚠️ via partners | ⚠️ внешним софтом | ✅ |
| Антропогенные звуки real-time | ❌ | ✅ | ❌ | ❌ | ✅ |
| Триангуляция | ❌ | ❌ | ❌ | ❌ | ✅ (v5) |
| Платформа для биолога | ❌ | ⚠️ | ✅ | ❌ | ✅ |
| Интеграция с гос. реестрами (ФГИС ЛК и т.п.) | ❌ | ❌ | ❌ | ❌ | ✅ |
| Российский cloud-стек (YC) | ❌ | ❌ | ❌ | ❌ | ✅ |
| Open-source готовность | ✅ | ⚠️ | ❌ | ❌ | ✅ (план) |

**Наш сильный нарратив:** мы единственные в РФ, кто строит вертикально-интегрированную систему PAM от датчика до платформы для ООПТ, на отечественном cloud-стеке, с возможностью отдать в open source.

## 4. Пилот с Yandex Cloud — детально

### 4.1 Цель

Доказать, что облачная часть Faun способна обработать данные Романа (180 ГБ) и выдать пользовательски-полезный результат с управляемой инфраструктурой Yandex Cloud. Получить базу для решения о следующей фазе.

### 4.2 Скоуп

**Входит:**

- Загрузка данных из Я.Диска Романа в Object Storage YC.
- Inference на BirdNet поверх всего корпуса 180 ГБ.
- Генерация CSV-отчёта: `трек / секунда начала / длительность / вид / вероятность`.
- Минимальный web-эндпоинт: вставить URL Я.Диск-папки → запустить job → получить ссылку на CSV.
- Логи + мониторинг базовый (Cloud Logging).
- Опция: дообучение модели под 1–2 локальных вида (если потребуется — см. сценарий high).

**НЕ входит** (явно):

- ❌ Real-time inference (батчевая обработка).
- ❌ Edge на ловушке.
- ❌ LoRa / УКВ / GSM передача.
- ❌ Триангуляция / локализация источника звука.
- ❌ Антропогенные звуки (бензопила/выстрел/мотор/голос).
- ❌ Гарантия accuracy >80% (BirdNet даёт 70–80% на чистом аудио, мы это и закладываем).
- ❌ Интерактивный дашборд с картой (это уже Faun-vertical 2).
- ❌ Hardware (датчики, edge, питание).
- ❌ Закупка железа.

### 4.4 Deliverable пилота

К концу пилота заказчик получает:

1. Работающий web-эндпоинт (`https://faun-pilot.<...>.cloud.yandex.net/` или аналог).
2. Один или несколько CSV-отчётов по 180 ГБ Романа (формат описан выше).
3. Документация по pipeline + handover-инструкция для команды Сергея.
4. Краткий отчёт о качестве: какая accuracy получена на их данных, какие виды распознаны хорошо, какие плохо, что мешает, что улучшит.
5. Грубая оценка масштабирования: что будет, если объём вырастет в 10× (на терабайты).
6. Кодовая база pilot (git-репозиторий, опционально open source).

### 4.7 Стоимость

## 5. Дорожная карта за пределами пилота

### 5.1 Фаза 2: «Выход на рынок»

**Триггер перехода:** успешный пилот, стратегическое решение команды развивать Faun как продукт.

**Что меняется:**

- Закупка собственного железа: ~10–30 датчиков для пилотной территории. Кандидаты: AudioMoth (низ. ценовая ниша), Raspberry Pi-based (гибкость), партнёрство с MIEM/Бауманкой по кастомным микрофонным массивам.
- Включение в pipeline антропогенных звуков (наша сильная сторона из исходного Faun).
- Edge inference (лёгкая модель прямо на устройстве) + LoRa/УКВ-передача только событий.
- Триангуляция (наш TDOA v5 переезжает 1-в-1).
- Расширение видов: finetune под локальные виды Северо-Запада, плюс антропогенный класс.
- Применение/подача на акселерационные программы (Сбер 500 как наиболее очевидный кандидат).

**Что нужно от Yandex Cloud:** продолжение инфраструктуры пилота + DataLens для аналитического слоя.

**Грубая оценка** (детально в Прил. B): hardware закупка ~₽500K–1.5M (10–30 датчиков), команда работает уже на грантовых/проектных деньгах, cloud ~₽30–80K/мес на нашу часть.

### 5.2 Фаза 3: «Масштабирование»

**Триггер:** валидация бизнес-модели после фазы 2, интеграция в платформу ООПТ Президентского фонда природы.

**Что меняется:**

- Тираж железа на десятки/сотни ловушек на несколько ООПТ.
- Production cloud со SLA, multi-region, дисциплина по cost.
- Полноценная платформа: дашборд, мобильное приложение для инспекторов, API для интеграции с ФГИС ЛК и другими гос. системами.
- Open source ядра (как опция — обсуждается с Президентским фондом).

**Что нужно от Yandex Cloud:** партнёрский тариф / включение в платформу ООПТ как один из вертикальных продуктов.

**Оценка:** годовой OPEX ~₽3–10M в зависимости от размера сети, hardware CAPEX за каждый рост сети — отдельно.

### 5.3 Критерии перехода между фазами

| От → К | Критерии перехода (что должно случиться) |
|---|---|
| Pilot → Фаза 2 | (1) Подтверждена работоспособность cloud-pipeline. (2) Accuracy на данных Романа ≥ 65%. (3) Сергей одобряет дальнейшую инфраструктуру. (4) Команда принимает стратегическое решение развивать Faun как продукт. |
| Фаза 2 → Фаза 3 | (1) Развёрнута пилотная сеть на ≥ 1 ООПТ с реальными датчиками. (2) Получены events с антропогенными звуками. (3) Есть отчёты для биологов / инспекторов / директора ООПТ. (4) Подача в Сбер 500 (или аналог) прошла, есть институциональная поддержка. |

## 7. Риски и допущения

### Допущения (явные, чтобы Сергей мог их оспорить)

1. **180 ГБ ≈ 300–1000 часов аудио.** Точный объём зависит от формата записи (sample rate, mono/stereo, разрядность). Берём медиану ~600 часов для расчётов; уточним при получении данных.
2. **BirdNet ~ 1× real-time на 1 vCPU.** Стандартный показатель BirdNET-Analyzer на CPU. Уточним после baseline-прогона.
3. **Облачную подписку Yandex Cloud открывает Сергей** для пилота; мы не платим за облако напрямую.
4. **Accuracy 65–80%** — реалистичный диапазон BirdNet на полевых записях с шумом. >80% не обещаем (по совету Сергея 8 мая: «не обещайте того, чего не сможете сделать»).
5. **Команда Faun работает за свой счёт** на этапе пилота; финансирование команды обсуждается отдельно для фазы 2.
6. **Y.Диск как источник данных подходит** для пилота (Сергей 8 мая: «на S3 никто не запретил, если нужно — переложим»).

### Риски

| Риск | Вероятность | Воздействие | Mitigation |
|---|---|---|---|
| Данные на Я.Диске оказываются грязными (мало сигнала, много шума) | Средняя | Высокое (под угрозой smysl пилота) | Первый прогон на сэмпле 10 ГБ → честный сигнал → решение продолжать или просить курированные данные |
| BirdNet даёт <60% accuracy на их данных (плохой fit) | Низкая | Среднее | Запасной вариант — Google Perch 2 / finetune BirdNet под локальные виды (сценарий high) |
| Сергей не одобряет архитектуру | Низкая (он сам это предложил) | Высокое | Узкий созвон до начала работ, итерация по архитектуре до согласия |
| Доступ к облаку YC задерживается | Средняя | Среднее | Глеб параллельно гоняет baseline на public BirdNet test data на локальном железе |
| Скоуп ползёт (Роман просит триангуляцию / антропогенные звуки в пилоте) | Средняя | Высокое | Чёткая фиксация in/out scope в этом документе + в письме перед стартом |
| Команда не успевает за 6 недель | Низкая-Средняя | Среднее | Срок гибкий (нет жёсткого дедлайна по Жене), приоритет — качество |
| Конкуренция со стороны open-source (BirdNet free, RFCx есть) | Средняя | Низкое | Наша добавленная стоимость — облачная упаковка под YC + интеграция с платформой ООПТ + расширение видов |

## Приложение C. Технический стек пилота

**Backend:** Python 3.11+, FastAPI (или Cloud Functions), Docker, Pydantic.
**ML:** BirdNET-Analyzer (Python), TensorFlow 2.x. Опционально для high — Google Perch 2 (бенчмарк vs BirdNet).
**Хранение:** S3-совместимый Object Storage (YC), Managed PostgreSQL (S2.micro) для статусов job-ов в mid+.
**Оркестрация:** Cloud Functions с триггерами на Object Storage events; альтернатива — Yandex Workflows (у Faun уже опыт с ним из vertical 1).
**Веб:** API Gateway + Cloud Functions; static frontend (один HTML с JS-формой) хостится в Object Storage с public access.
**Мониторинг:** Cloud Logging (структурированные JSON-логи), Cloud Monitoring (uptime check на /health).
**CI/CD:** GitHub Actions → push образа в Container Registry → deploy в Compute Cloud (для mid+). У команды есть готовый шаблон из основного Faun.
**Конфиг:** Terraform для инфраструктуры (минимум — IAM, VPC, Object Storage buckets), `.tfvars` под три сценария.
