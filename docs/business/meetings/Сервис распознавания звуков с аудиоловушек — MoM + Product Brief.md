## 2\. Видение продукта (brief)

### Что мы строим (MVP)

Сервис для классификации звуков с аудиоловушек в заповедниках. Пользователь — сотрудник особо охраняемой природной территории.

**Базовый сценарий:** пользователь загружает WAV-файлы (10-минутные записи с ловушек) → сервис прогоняет их через классификатор → на выходе пользователь получает структурированный отчёт (CSV или аналог) с разметкой: имя файла / ловушка, timestamp события, метка классификации (вид животного/птицы/техногенный звук), степень уверенности модели.

### Что НЕ входит в MVP (vnext — следующие итерации)

- Кластеризация перемешанных записей по фоновому шуму  
- «Склейка таймлайна» из перемешанных фрагментов по граничным значениям спектрограмм  
- Триангуляция координат источника звука по разнице времени прихода  
- Edge-инференс — запуск модели на устройстве при ловушке  
- Передача событий по сети (GSM / LTE / Wi-Fi-мост / LoRa)  
- Любая хардверная составляющая

### Что точно НЕ наша зона ответственности

- Само железо аудиоловушек  
- Протоколы и каналы передачи данных  
- Установка устройств в полях

## 3\. Зафиксированные решения

1. **Формат входных данных:** работаем с существующим форматом ловушек — 10-минутные WAV-файлы, между записями \~1 минута перерыв. Каждая ловушка пишет в свою папку (А1, А2, …) с файлом `info.txt` (CSV-метаданные).  
2. **Timestamp:** берём из имени файла и `info.txt`. Таймлайн вручную не собираем.  
3. **Метаданные:** в `info.txt` уже есть всё нужное — date, time, координаты, температура, влажность, sample rate, gain. Дополнительной интеграции не требуется.  
4. **Разметка на старте:** не нужна. Используем BirdNET и существующие открытые датасеты \+ чистку фонового шума по записям самих ловушек (есть запись «жужжания» ловушки в офисных условиях для вычитания).  
5. **Формат выгрузки результатов:** базовый — CSV. Колонки: имя файла / ловушка, timestamp, метка, confidence.  
6. **Хранение и передача данных от пользователя:** через Я.Диск (Роман подтвердил — у заповедника уже работает такая схема). Возможна интеграция с Я.Облаком.  
7. **Hardware и связь — НЕ наша зона.** По железу и каналам передачи коннектимся к инженерам, контакт которых дали в Яндексе (вероятно — лаборатория связи, не акустики).  
8. **Каналы передачи:** не изобретаем свой протокол. Используем готовые — GSM / LTE / Wi-Fi-мост в зависимости от условий. LoRa и любая нестандартная радиосвязь — НЕ идём этим путём.  
9. **Координаты ловушек:** заполняются на самом устройстве, попадают в `info.txt`. Дополнительной разметки локаций от пользователя не требуется.  
10. **Сроки разработки MVP:** активная разработка — после сессии команды (предположительно с начала июля). Длительность — ориентировочно 2 недели интенсивной работы. Без привязки к фиксированным датам.  
11. **Демо MVP:** первую версию показываем Роману. Точные сроки демо — TBD, по факту готовности.
