## Коротко (вывод сначала)

Пайплайн birds-baseline работает и задеплоен (Perch 2, реальное распознавание, не заглушка).
Целевая задача проекта — **скрытные млекопитающие** (садовая соня, выхухоль) — упирается в один
факт: **размеченного аудио этих видов нет нигде** — ни в репозитории, ни на кластере, ни в открытых
датасетах (подробности — `docs/ДАННЫЕ-ИНВЕНТАРЬ.md`, `docs/БРИФИНГ-ML.md`). Это не баг и не забытая
задача — это единственное узкое место, вокруг которого выстроен весь дальнейший план
(`docs/ПЛАН-ДАЛЬНЕЙШИХ-ДЕЙСТВИЙ.md`). Механизмы для получения меток (review-петля, xeno-canto
few-shot) уже построены и ждут данных.

Отдельно — у документации накопился дрейф от кода: часть доков называет устаревший тег прод-образа,
часть всё ещё говорит «птицы» вместо «птицы = baseline, млекопитающие = цель», часть просто
недостижима из навигации сайта. Это тоже разобрано ниже, отдельным разделом, без исправлений на
живую — где правка спорная (регион, keep/archive), решение за владельцем.

## 1. Что OK

- **Прод жив и распознаёт реально.** `faun.antopkin.ru/` → `faun-api` на кластере, классификатор
  `perch-v2` (не Stub), HTTP Basic Auth включён. Задокументировано в `CLAUDE.md` (раздел
  «Инфраструктура») и в памяти сессий.
- **Тесты и safety-гейты зелёные.** Последний известный прогон на HEAD `9ccad2a` — 630
  passed / 2 skipped, bandit 0 HIGH (см. §3 ниже — эта цифра нигде не записана в самих доках).
- **Двухэтапный контур birds-baseline работает end-to-end**: детектор событий → Perch 2
  zero-shot/proба → CSV + `detections.jsonl` → review-UI лесника → export-labels → retrain. Каждое
  звено этой цепочки реально закодировано и покрыто тестами (`faun/pipeline`, `faun/detections`,
  `faun/api` роут `/review`, `faun/cli export-labels`, `faun/retraining`).
- **Волны 1–5 (2026-06-24) аддитивны и по умолчанию выключены** — golden-поведение пайплайна
  байт-в-байт не изменилось. Это подтверждено при мёрже и не переоценивается здесь заново.
- **Механизм ranger-разметки готов и работает как замкнутая петля**: `POST
  /jobs/{id}/detections/{det}/label` (UI `/review`, аудиоплеер реального клипа) → `faun cli
  export-labels` (только `is_ground_truth`-метки) → `faun retrain`. Готов принять реальные метки
  млекопитающих в тот день, когда они появятся.
- **Механизм xeno-canto few-shot готов и заморожен**: `experiments/exp_e10.py` (Perch-эмбеддинги +
  косинусный k-NN для сони/выхухоли) сейчас SKIPPED (нет ключа/данных), но запустится без
  изменений в коде, как только появятся файлы под `datasets/xeno_canto/<species>/*.wav`.
- **Routing-сигнал «птица vs не-птица» (p_bird) эмпирически валиден**: ROC-AUC 0.9962 (Perch) /
  0.9969 (YAMNet) на ESC-50. Калибровка этого порога НЕ требует меток млекопитающих — это чисто
  инженерная настройка, уже реализованная (`bird_presence_mass`, `apply_presence_gate`,
  `STATUS_REJECTED`).
- **Второй классификатор для млекопитающих не требует GPU.** Путь «YAMNet-эмбеддинги + лёгкая
  прототип-проба с классом `__negative__`» — sklearn/numpy-проба поверх замороженного эмбеддера, не
  тяжёлый fine-tune. Уже провалидирована на кластере (CPU, throwaway-контейнер): macro-F1 0.8434 на
  50-видовом held-out **iNatSounds** (птицы, не млекопитающие — это проверка метода, не измерение
  целевых видов).

## 4. Где мы относительно плана пилота

Пилот стартует с июля (Yandex Cloud + Президентский фонд природы). Дифференцирующая задача —
распознавание скрытных млекопитающих (садовая соня, выхухоль); птицы — уже работающий baseline
поверх Perch 2.

- **Есть**: работающий пайплайн детекции + birds-классификации, задеплоенный на прод; замкнутая
  петля review→export-labels→retrain; готовый (но не запущенный) механизм few-shot под xeno-canto;
  готовый (CPU-only) метод второй модели — YAMNet-эмбеддинги + прототип-проба с классом
  `__negative__`.
- **Нет**: ни одного размеченного клипа целевого вида где-либо (raw180 без меток; ESC-50 — общие
  бытовые классы, целевых видов нет; iNatSounds знает таксон садовой сони, но 0 аннотаций для него;
  выхухоль отсутствует среди всех 5569 категорий iNatSounds). Это единственное узкое место —
  подробности в `docs/ДАННЫЕ-ИНВЕНТАРЬ.md` и `docs/БРИФИНГ-ML.md`.
- **Заблокировано (не критично для пилота)**: тяжёлый fine-tune аудиотрансформера (`faun/training`,
  PaSST/AST/BEATs) — тройной блок (GPU занят демо v1 + нет serving-адаптера чекпойнта + нет данных
  для дообучения). Для второй модели пилота фактически не нужен — YAMNet+проба идёт CPU-only.

## 5. Вопросы к владельцу (эскалация, не решать самостоятельно)

Ниже — то, что по фактам репозитория решить нельзя: либо нужен эксперт-биоакустик/лесник, либо это
продуктовое или архивное решение. Ничего из этого в рамках Wave 1 не менялось.

- **Legacy-архив (`legacy/`, старые бизнес-документы v1)**: оставить замороженным как сейчас, или
  куда-то вынести из основного дерева репозитория? Сейчас это рабочее состояние («не трогаем»), но
  решение оставить так навсегда или переместить — за владельцем.
- **`faun/storage` — держать под будущий S3-бэкенд («задача на июль») или заархивировать как
  неиспользуемое?** По фактам это орфан относительно текущего пайплайна, но он написан заранее под
  конкретную будущую задачу — решать, что с ним делать, владельцу, не по факту «раз не используется,
  удалить» (правило проекта — не удалять чужой рабочий код без запроса).
- **Правовые доки не про тот регион**: `docs/legal/07_lesnoy_plan_nizhegorodskaya.md`,
  `docs/legal/08_gosprogramma_les_nizhegorodskaya.md`, `docs/legal/09_nizhegorodskaya_specifika.md`
  и `docs/protocol_legal_basis.md` целиком описывают Нижегородскую область (v1-хакатон, Варнавино).
  Реальные записи заказчика сделаны у деревни Ковкеницы, Ленинградская обл. (рядом с
  Нижне-Свирским заповедником) — это подтверждено телеметрией `raw180/A{1-4}/info.txt` и уже
  зафиксировано в `docs/АУДИТ-2026-06-25.md`. Сейчас ни один правовой документ верный регион не
  называет вообще. Это уже отмечено как известная проблема, но сами файлы не помечены и не
  переписаны — решение (переписывать под верный регион, готовить новый набор доков, или просто
  пометить как «не относится к заказчику») за владельцем, не за агентом.
- **Официальный чеклист видов заповедника**: у нас его нет и не подавали на вход. Единственный
  «чеклист» в репозитории (`faun/data/reserve_checklist.txt`) явно помечен как список, составленный
  ассистентом по общим знаниям, а не полученный от заповедника или лесника — использовать его как
  источник истины нельзя.
- **Полоса вокализации целевых видов**: пайплайн классифицирует после ресэмплинга до 16 кГц (то
  есть физически видит только до ~8 кГц по теореме Найквиста). Вокализируют ли садовая соня и
  выхухоль в этой полосе, или запись нужно обрабатывать в более высокой полосе — вопрос к
  специалисту по биоакустике, репозиторий на него ответить не может.
- **Цена ошибки (пропуск редкого зверя vs заваленная очередь ревью лесника)**: механизм для
  настройки этого баланса уже есть в коде (порог presence-gate), но какие веса выставить — решение
  владельца/лесника, не инженерный вопрос.
- **UX разметки лесником (CSV-импорт vs UI, выпадающий список vs свободный ввод, каденс batch)**:
  оба технических пути построены и рабочие; какой предпочесть под реальный процесс лесника —
  решает владелец/лесник, не код.
